# Manager v1 验证记录

验证环境：Windows、Java 25.0.2、MATSim 2026.0；仅本地 mock/fixed/规则和本地伪 HTTP 服务，没有调用真实付费 LLM。以下是工程验证，不是拥堵收费效果实验。

## 自动测试

- Java 单元及集成测试：参数/路段权限、价格索引与时段边界、不可变快照、规则阈值、观测不足保持、API/JSON 错误保持、重复 JSON 键/尾随文本拒绝、更新/冻结时点、历史长度。
- 本地 HTTP 服务验证 Manager 请求包含提示、知识、场景、权限和政策，并验证远端错误正文不泄露到异常消息。
- 小路网真实 QSim 对照：同一固定路线，off 与 shadow 得分相同；active 第 1 轮仅扣一次 2 单位费用，货币边际效用 0.5，得分差恰为 -1。
- 路径搜索测试：发布收费后，同一个路由器读取新价格快照，改选成本较低的替代路径。
- Python 测试：按 car 与进入时刻分格、未完成通行不计入完整路段指标、收费事件拒绝、gzip/zstd 读取。

## Sioux Falls 应用烟雾测试

使用本机既有 Sioux Falls 输入，人口 84,110，2 名 mock 控制出行者，迭代 0–1，临时 fixed Manager。仅为测试选择路段 `10_2`，全天单格、费用 2、预热 1 轮。这个测试路段和价格没有写入正式配置模板，也不构成候选选择建议。

- 应用正常结束；第 0 轮价格为 0，第 1 轮价格为 2。
- 收费日志中第 0 轮无缴费；第 1 轮有 3,689 笔，共 7,378 场景货币单位。
- 生成 `llm-action-memory-policy-0.csv`，确认政策变化前统计存档通路正常。
- 对第 0 轮 `.events.xml.zst` 运行基线分析脚本：路段 `10_2` 完整通行数 1,643，平均延误 0.6212800746278635 秒，与 Java 在线观测一致。
- 两轮不是充分适应的实验，且存在大量未完成 car leg；不据此声称收费降低了拥堵、改善了福利或确定任何阈值。

本机日志和输出位于忽略目录 `output/manager-smoke-20260907`，临时测试配置在 `target/manager-smoke-only.json`。它们不随源代码提交。正式运行请依据 [使用说明](manager.md)，先完成独立无收费基线并确认候选集合。

# Traveler 默认运行协议

本项目默认采用五日 Traveler 反思、五日决策历史、日末角色反思并行和相对计划时间 `[-60,+30]` 分钟的出发窗口，间隔 15 分钟，即 −60、−45、−30、−15、0、+15、+30 分钟；边界还受活动起始时间、零点与 QSim 终止时间约束。不再需要选择版本。旧脚本中的 `--v2` 仅作为隐藏兼容参数接受，不改变设置。

五日反思要求 Java LLM Traveler 且不启用语义复核；可通过 `--traveler-reflection-interval 1` 调整反思周期。`--no-parallel-role-reflection` 可以关闭角色并行；出发窗口参数可单独设置。输出 manifest 记录实际设置，而不是根据目录名推断。

知情旅客能看到当前全网收费规则，未列出收费规则的路段和时段为零收费。不知情旅客看不到公告：对每条路段及对应时间分箱，使用自己此前最新一次实际经过的收费观察（包括零），未观察部分按零估计。零是未经证实的初始估计，旧观察也可能过时；实际扣费始终根据进入路段时的当前政策。收费政策更新不会自动改变不知情者的历史记录。Traveler-only 和 Manager 的免费期使用相同信息接口，不保证模型输出或交通执行逐次完全一致。

## 日末流程

1. MATSim 结束当日执行，记录 Traveler 的个人事实并整理 Manager 可见的公共交通反馈。
2. 满足 Traveler 反思日时，Traveler 读取上一份摘要与自上次反思以来的个人执行事实，调用 LLM 生成新摘要；非反思日继续沿用已有摘要。Manager 按其原有机制每日反思。
3. 当两类反思同时发生时，从各自允许的信息快照发起请求；等请求完成后才提交结果并推进后续步骤。Manager 不读取 Traveler 私人记忆。
4. 下一天的决策使用已提交的可用状态。Manager 当天若有政策更新，仍须先确定政策，再向需要该公告的 Traveler 发起选择。

以首次迭代对应的仿真日为第 1 天，Traveler 在第 5、10、15 天等日末反思；结束日不是反思日时不额外补做。第一次反思前摘要为空，直到首次完成后才有 LLM 生成的摘要。反思输入覆盖自上次反思以来的执行事实，包括可用的实际支付；缺失或未完成结果仍按原记录含义处理。事实与主观摘要分开，不应把模型文字视为已验证的事实。

`--traveler-reflection-interval` 是 Traveler 反思间隔；未显式设置历史窗口时，决策窗口随反思间隔设置为相应的 1 或 5 天。显式 `--history-window` 可覆盖为 1–5 天。该间隔不改变 Manager 每日反思、收费政策更新间隔、MATSim 仿真天数或 Traveler 每日决策次数。并行隐藏的是可重叠的等待时间；两个 API 仍各自产生请求和费用，且下一日开始前需完成相应状态提交。

## 调用量与核查

若有 N 个受控目标行程、D 个仿真日，基础 Traveler 调用数约为 `N × (D + floor(D / 5))`：每天一次决策，每五天一次反思。独立 Manager 的每日反思、政策更新、输出校验重试和可选额外调用另计。实际耗时取决于模型服务吞吐、流量仿真以及重试，不能直接按调用次数推算墙钟加速。

短运行可选 11 天，检查第 5、10 天存在 Traveler 反思，第 11 天不会自动补做；再检查每日决策、公共反馈与独立 API 调用。根据输出核对 `morning/manifest.json` 的 `experimentProtocolVersion`、`travelerReflectionInterval`、`parallelRoleReflection` 和 `departureProtocol`，以及 `api-usage.json`、`memory-contexts.jsonl.gz`、`memory-updates.jsonl.gz` 和 Manager 对应记忆记录，确认日期、反思输入和调用次数符合设置。基础请求预算预检按所设反思周期估算；应另外为重试预留余量。使用不同模型服务时，先分别验证连通性和配额。

不同反思周期会改变可用记忆及其形成时间；比较时应固定其他配置并进行独立重复。

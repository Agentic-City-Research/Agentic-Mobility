# AgenticMobility 实验平台：功能与设置说明

本文依据当前 `AgenticMobility-v2` 的 Java 实现、默认场景和运行脚本整理，适用于从项目根目录运行的实验。当前标准旅客协议已是默认设置，无需额外指定 `--v2`。文中的“天”指一次 MATSim iteration；代码中的 `day=0` 是第 1 个仿真日。参数和默认值可能被命令行、环境变量或配置文件覆盖，具体实验应以其 `morning/manifest.json`、`effective-config.xml` 和实际运行命令为准。

## 1. 平台能做什么

平台在全天 MATSim 交通仿真中，让选定的目标旅客进行路线与出发时间决策，并可叠加固定收费或 LLM Manager 收费。其他旅客及目标旅客的其他行程继续参与同一交通系统。每个仿真日执行交通模拟，记录实际行程及收费，再将允许看到的个人经历或公共统计用于后续决策。

实验按照**旅客行为**和**收费条件**两个维度分类，共有下表中的九种组合；它们使用同一主实验流程。受控旅客只覆盖选中的目标行程，其他人和其他行程继续参与原生交通。

| 旅客行为 | 无收费、无 Manager | 固定收费、无 Manager | LLM Manager 动态收费 |
| --- | --- | --- | --- |
| MATSim 原生旅客 | 原生基线：不控制目标旅客 | 原生旅客 + 固定收费 | 原生旅客 + Manager |
| MNL 受控旅客 | MNL 基线 | MNL 旅客 + 固定收费 | MNL 旅客 + Manager |
| LLM 受控旅客 | LLM 基线 | LLM 旅客 + 固定收费 | LLM 旅客 + Manager |

旅客通过 `--llm-agents 0` 选择原生行为；使用 `--policy mnl --llm-agents all` 或 `--policy llm --llm-agents all` 控制所有符合条件的目标人，也可用正整数控制部分目标人。收费条件通过不添加收费参数、使用 `--fixed-toll-policy`、使用 `--manager` 三选一；固定收费与 Manager 不能同时启用。Manager 可在不同政策更新日调整收费，但每条已接受规则覆盖整个仿真日，不代表日内分时调价。收费单位是场景货币单位。九种组合是平台支持的配置，并非每项研究都必须运行全部组合。

核对实际运行时，可组合查看 `morning/manifest.json` 中的 `choicePolicy`、`controlledPersons`、`controlledTrips` 和 `pricing.mode`（`none`、`fixed` 或 `manager`）。这比仅看请求参数 `--policy` 更可靠：例如受控人数为 0 时，`--policy mnl` 对应的是原生旅客。

原生和 MNL 本身不调用模型 API；LLM 旅客需要旅客模型服务。启用 Manager 后，不论旅客类型如何，Manager 从免费期第 1 天起都需要模型服务进行每日反思。只有同时包含 LLM 旅客和 Manager 的组合需要两种角色的模型调用。

默认 `--information-scope controlled` 仅将受控旅客纳入知情/不知情分组；因此原生组 `--llm-agents 0` 的默认分组范围为空。如需对原生旅客研究信息差异，应指定 `--information-scope all`，并核验实际分组与路由设置。

**注意默认组合**：入口默认 `--mode hybrid --policy mnl --llm-agents 0`。`0` 表示没有受控旅客，因此直接使用默认值运行的是原生旅客基线；要实际使用 MNL，须将 `--llm-agents` 设为 `all` 或正整数。

## 2. 仿真环境与每日流程

默认入口为 `org.matsim.agentic.MorningExperiment`，默认配置是 [Sioux Falls 配置](../scenarios/SiouxFalls-public/config.xml)。该场景以 car 为路网主要出行方式，配置了步行接驳，QSim 默认运行至 30:00；具体路网、人口、设施、容量和重规划参数由配置及实际输入决定。Java 源码要求 JDK 25。

典型的一天按以下顺序执行：

1. 根据运行配置准备当日人口计划；在需要更新政策的日期，Manager 根据已有历史公共反馈提出并校验收费政策。
2. 选定目标旅客在既定候选路线和出发时间中作选择；未受控部分继续使用相应原生重规划。
3. QSim 按实际路网运行，记录车辆进入路段、旅行时间、到达或失败、实际收费等。
4. 更新个人实际经历和收费认知，汇总路网指标；按设定周期执行旅客反思，并在启用时进行 Manager 日终反思。
5. 保存当日指标、决策和相关审计记录，供后续日期及实验分析使用。

Manager 与旅客反思可在公共观测固定后并行执行；这是运行并发设置，不意味着两者可以看到对方的私人记忆。

主实验默认保留原生 `TimeAllocationMutator`，可用 `--no-native-time-mutation` 关闭；`--innovation-stop-day` 可覆盖原生创新策略停止日。两组实验是否启用这些机制会影响结果，必须记录。`--mode hybrid` 可显式指定，但无需把实验组合划分为不同运行模式。

## 3. 人口、目标行程与抽样

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--demand` | `200` | 选择项目数据的 200% 需求；也可设为 `100`。 |
| `--population` | 未指定 | 可覆盖人口输入文件。 |
| `--cohort-selection` | `planned-arrival` | 按原始计划选定目标行程，成员在实验中固定。 |
| `--planned-arrival-before` | `32400` | 默认目标行程的原计划目的地活动开始时间早于 09:00；不是出发时间早于 09:00。 |
| `--peak-start` / `--peak-end` | `25200` / `32400` | 选择 `planned-departure` 时，原计划出发时间窗口为 `[07:00, 09:00)`。 |
| `--llm-agents` | `0` | `0`、`all` 或受控人数；名称沿用历史写法，也用于选择 MNL 受控人数。人数与目标行程数不一定相同。 |
| `--days` | 未指定 | 显式指定总仿真天数；省略时沿用 config 的首末 iteration。所附 config 为 0–3000，不等同于 100 天。 |
| `--seed` | 未指定 | MATSim 仿真随机种子；省略时由配置文件决定。 |
| `--population-seed` | `4711` | 人口抽样及默认分组/画像种子，与 `--seed` 独立。 |

两种抽样方式互斥：

- `--sample-persons N`：固定人数的诊断样本，**不按人数缩放容量**，适合检查程序，不应直接当作正式比例样本。
- `--sample-rate k`：固定抽取比例 `0 < k ≤ 1`；流量容量系数为 `k`，存储容量系数为 `k^0.75`，相对于原始路网容量设置。

## 4. 旅客的路线、时间与画像

### 4.1 候选路线

平台为目标 OD 生成固定候选路线，使用 BFS-LE 搜索，最多提供 4 条；受到路网和筛选条件限制时可能少于 4 条。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--candidate-pool-size` | `16` | 筛选前最多收集的不同路径数量，须至少为 4。 |
| `--candidate-search-limit` | `10000` | 每个 OD 搜索状态的上限。 |
| `--candidate-max-time-ratio` | `2.5` | 相对 `c0` 自由流时间的比例上限；允许额外 `--candidate-time-slack-seconds 300`。 |
| `--candidate-max-distance-ratio` | `2.5` | 相对 `c0` 距离的比例上限；允许额外 `--candidate-distance-slack-meters 2000`。 |
| `--candidate-max-overlap` | `0.85` | 两条路线共享有向路段长度相对较短路线长度的上限；`1` 关闭该限制。 |
| `--candidate-order` | `original` | 候选呈现顺序：`original`、`reverse` 或 `shuffle`；`--candidate-order-seed` 默认 `0`。 |
| `--candidate-file` | 未指定 | 复用既有候选文件；缺少目标 OD 时失败，不会静默重新生成。 |

候选文件是否适用于某次实验，取决于其覆盖的目标 OD、路网和实际人口样本，不能仅凭 `candidates_100.jsonl.gz` 或 `candidates_20.jsonl.gz` 文件名判断。复用时检查输入哈希、目标 OD 覆盖和运行记录。

### 4.2 出发时间

LLM 和联合 MNL 从“候选路线 × 离散出发时间”中选择。时间网格以原始计划出发时刻为锚，默认允许提前 60 分钟、延后 30 分钟，间隔 15 分钟，即原计划的 `-60、-45、-30、-15、0、+15、+30` 分钟；还会受到合法活动时序及仿真边界约束。设置为 `--departure-before-seconds 3600 --departure-after-seconds 1800 --departure-step-seconds 900`。边界须为步长的整数倍。

### 4.3 个人画像

`--personal-profiles legacy` 为默认值，使用固定的合成画像；它是实验假设，并非真实调查数据。`--personal-profiles input` 仅使用输入属性。可用 `--profile-seed` 独立设置画像种子，或用 `--profile-file` 复用已有画像；后者要求 `legacy` 模式且覆盖所有受控人。

| 维度      | 类别                                     | 当前提示中的作用                            |
| ------- | -------------------------------------- | ----------------------------------- |
| 收入/资源条件 | HIGH、MEDIUM、LOW                        | 描述通勤费用对预算的压力，不指定时间价值或费用系数           |
| 决策风格    | CONSERVATIVE、AGGRESSIVE                | 描述对熟悉性、可预测性及未知选项的态度，不代表驾驶方式或驾驶速度    |
| 工作时效偏好  | MUST_ON_TIME、SLIGHT_LATE、EARLY_ARRIVAL | 描述准点重要性、少量迟到态度及提前准备偏好，不设置类别专属数值容忍时间 |
当前代码的三类收入是费用压力的自然语言合成标签，不按真实家庭收入赋值或抽样，不从类别推导时间价值。前期讨论另提出借鉴 Pew 相对收入分层、以 Sioux Falls 家庭年收入中位数 75,970 美元（2024 年美元计）作解释示意，得到下表；这些数值尚未进入当前默认提示或人口分配。正式采用前需保留统计来源、年份和家庭口径，不能把本表写成已实施的现实人口校准。

| 类别         | 家庭年收入（美元）            | 简便记法           |
| ---------- | -------------------- | -------------- |
| **LOW**    | 低于约 **50,647**       | 低于约 5.1 万      |
| **MEDIUM** | 约 **50,647—151,940** | 约 5.1 万—15.2 万 |
| **HIGH**   | 高于 **151,940**       | 高于约 15.2 万     |

当前默认三个维度均独立、等概率分配，单次运行内固定；实际十八类人数不保证严格等分，收入也不按本市人口比例分配。画像随机性按 personId 和 seed 确定，也支持导入已有画像。画像不修改原生评分函数或工作截止时刻。

通勤目的地 `work` 当前要求不晚于 9:00 到达。到达晚于 9:00 才记为迟到；该要求不保证执行时必然满足。非工作行程不因画像自动生成工作截止时间。
## 5. 旅客决策模型与记忆

### 5.1 LLM 旅客

`--policy llm` 使用模型在合法候选集合中选择路线和出发时间，并生成简短理由。平台检查 JSON、路线 ID、时间选项及长度，非法输出按 `--repair-attempts` 重试；无法完成时实验会报错。决策上下文包含允许看到的路线事实、个人属性、个人经历和收费认知，不能读取 Manager 私人记忆或其他人的经历。

| 参数                                    | 默认值        | 含义                                                     |
| ------------------------------------- | ---------- | ------------------------------------------------------ |
| `--history-days` / `--history-window` | 随反思周期，默认 `5` | 决策前近期个人事实窗口，允许显式指定 1–5 天；LLM 另包含最近一次成功摘要之后所有尚未总结的经历。 |
| `--traveler-reflection-interval`      | `5`        | 旅客反思间隔，仅支持 1 或 5 天。                                    |
| `--memory-max-chars`                  | `500`      | 个人摘要硬上限，范围 1–500 字符；提示目标为约 240 字符。                     |
| `--memory-max-output-tokens`          | `1024`     | 旅客反思输出上限。                                              |
| `--traveler-memory-variant`           | `original` | 可选 `dedup-prompt`、`ledger`；变体要求 Java LLM 旅客，且不能启用语义复核。 |
| `--traveler-semantic-review`          | 关闭         | 可选的模型语义复核，会增加调用；要求反思间隔设为 1。                            |

Java 旅客反思是批量提交：全部旅客的反思成功后才更新摘要；批量失败会中断运行，不会部分提交。默认每 5 天反思，决策时查看前 5 天的近期经历；未总结经历也会直接进入决策输入，避免事实缺口。选择每日反思时，未显式指定的决策历史窗口随之设为 1 天；如单独指定 `--history-window`，以显式值为准。

可选 Python 旅客桥接通过 `--python-agent-url` 和 `--python-backend baseline|v9|concordia` 同时指定；它要求 `hybrid` + `llm`、反思间隔为 1，不能与当前 Java Manager 或 Java 语义复核同时使用。

完整提示词、动态输入结构及审计方法见 [Agent 提示词说明](agent-prompts.zh.md)。

### 5.2 联合 MNL

`--policy mnl --llm-agents all` 使用多项 Logit 在相同的路线 × 出发时间动作中选择。每个动作的效用为：

`V = -a × 预计汽车时间 - b × 预计收费 - c × 预计迟到 - d × |出发时间相对原计划的偏移|`

时间以分钟计，收费以场景货币单位计。概率由 softmax 计算；按选择种子、day 和 tripId 派生随机流。时间预期使用自由流时间与近期本人同路线、同计划出发时间分箱内的完成经历融合；无匹配经历时回退自由流，未完成行程不当作零耗时。

默认参数文件为 [mnl-joint.example.json](../config/baselines/mnl-joint.example.json)：时间、收费、迟到、出发偏移系数分别为 `0.3、0.3、0.9、0.05`；经历权重 `0.5`，经历时间箱 `900` 秒。**这些是未校准的工程示例，不是实际人群估计值。**可用 `--mnl-parameters` 指定带单位和来源的参数文件，`--mnl-choice-seed` 默认跟随仿真种子。参数及输入哈希写入实验记录。

`shortest` 与 `mock` 也可作为程序检查或辅助对照策略；它们不等同于经过校准的行为模型。

## 6. 收费认知、信息分组与实际收费

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--information-scope` | `controlled` | 仅对受控人赋予信息组和个人收费认知；`all` 扩展至全体人口。范围之外的人保留原生公共政策路由。 |
| `--informed-share` | `0.5` | 信息范围内的知情者比例，范围 0–1。 |
| `--information-seed` | 人口种子 | 独立、固定的信息分组种子。 |
| `--toll-history-bin-seconds` | `3600` | 个人收费经验的路段 × 时间箱宽度。 |

例如，原生旅客 + Manager 若使用 `--llm-agents 0` 且保留默认 `controlled`，信息分组范围为空；如需将全体原生旅客纳入信息分组，应显式指定 `--information-scope all`，并检查实际分组记录。

知情者可使用当前公开收费政策；不知情者不接收最新政策，只按自己实际经过的路段和时间箱的最近观察估计收费。未观察部分以零作为预期，但这不代表实际免费：实际经过时始终按执行中的政策收费，观察到零也更新经验。路线预期收费基于预计进入时间，实际账单基于实际进入时间，两者可能不同。

收费按实际汽车路段进入事件计算，包含起点部分路段；重复经过可再次收费，重复的同一入路通知会去重。`toll-observations.jsonl.gz` 是研究者内部逐事件账本，只覆盖参与个人收费认知的人，包含零收费观察；范围外人员的正收费仍可能出现在 `toll-payments.jsonl.gz`。账本不应整体提供给不知情旅客。

## 7. 收费政策与 Manager

### 7.1 固定收费

`--fixed-toll-policy <JSON>` 在运行前加载并校验固定政策，适用于 `hybrid`，与 `--manager` 互斥。规则包含 `link_id`、`start`、`end`、`amount`，时间区间左闭右开；同一路段收费时窗不能重叠。`--fixed-toll-free-days` 默认为 20，设为 0 则首日生效。运行中修改输入文件不会改变已加载政策。格式与示例见 [固定收费说明](../scenarios/SiouxFalls-public/fixed-tolls.md)。

### 7.2 LLM Manager

使用 `--manager` 启用。默认前 20 个仿真日免费观察，第 21 日首次可更新政策，之后 `--manager-update-interval` 默认每 30 天更新一次，即第 21、51、81 日等；具体是否收费取决于模型输出和校验。政策输出反复不合法时跳过更新并保留原政策；模型调用等运行异常可能中断实验。Manager 每个完成日都会进行记忆反思，包括免费期；反思失败时保留旧管理记忆，下次反思补充缺失期间的公共汇总。

Manager 可见全网公共拓扑、聚合交通和收费反馈、执行中的政策与管理记忆；不读取个人画像、个人旅客记忆或逐人账单。反馈包括路段通行/延误、收费收入，以及全体计划汽车行程的出发、完成、中止、未完成、未出发数量和全天汽车人时。

汽车人时从汽车出发至到达，包含入网前等待。只有全部计划汽车行程完成时 `carPersonHours` 才是完整总量；否则为 `null`，另给截至仿真结束的已观察耗时下界。入网前等待的完成者统计只覆盖已完成且观测到入网事件的行程；不能解释为全体等待总量。

| Manager 配置 | 实际约束 |
| --- | --- |
| `--manager-profile basic`（默认） | 每路段最多一条规则、总计最多 40 条，金额有限且非负，每条规则覆盖完整仿真日；不启用额外价格上限、涨幅上限或自动撤回。 |
| `--manager-profile controlled` | 在上述规则外增加可配置研究约束及自动审查/撤回。默认等效收费上限 5 分钟、单次涨价上限 2 分钟、最多 1 个收费走廊、每走廊 1 个收费路段、不可避免比例阈值 0.5。 |

`controlled` 默认复核 7 天、适应 7 天、连续违规 3 次、冷却 7 天，可通过 `--manager-review-days`、`--manager-adaptation-days`、`--manager-breach-days`、`--manager-cooldown-days` 调整。这些是实验保护条件，不是经标定的最优收费。

## 8. 模型服务与调用设置

Java 客户端使用兼容 Chat Completions 的服务。程序**不会自动加载 `.env`**；需在启动环境中设置环境变量，或通过 CLI 指定非密钥配置。常用设置如下：

| 设置 | 默认值或说明 |
| --- | --- |
| `AGENTIC_API_KEY` | 模型服务密钥；通过环境变量提供，不写入命令、文档或实验记录。 |
| `AGENTIC_MODEL` / `--model` | 默认 `deepseek-flash`。 |
| `AGENTIC_BASE_URL` / `--base-url` | 默认 `https://api.deepseek.com`；可指向兼容服务。 |
| `--temperature`、`--top-p` | 默认不强制设置；可按服务支持情况指定。 |
| `--generation-seed` | 服务端生成种子，与 MATSim 仿真种子独立；能否确定复现取决于服务。 |
| `--response-format` | 默认 `omit`；也可选 `json_object`、`json_schema`，应先确认服务支持。 |
| `--concurrency` / `--repair-attempts` | 默认 `8` / `3`。 |
| `--timeout-seconds` / `--llm-stall-seconds` | 无环境覆盖时默认 `300` / `600` 秒；后者是无进展阈值。 |
| `--max-requests` | 无环境覆盖时默认 `25000`，`0` 表示不限；所有角色及重试共享预算。 |
| 旅客决策 / 旅客反思输出上限 | 默认分别为 `1024` / `1024` tokens，可独立设置。 |
| Manager 政策 / Manager 反思输出上限 | 默认分别为 `8192` / `2048` tokens，可独立设置。 |

Manager 默认继承旅客服务配置，也可用 `--manager-model`、`--manager-base-url` 和 `AGENTIC_MANAGER_*` 覆盖。若 Manager 使用不同 endpoint，需显式指定 Manager 模型及 `AGENTIC_MANAGER_API_KEY`；程序不会将旅客密钥发送到不同服务。

以默认更新间隔运行 100 天的 Manager，至少有 100 次每日管理反思和 3 次政策调用；旅客选择、旅客反思、重试及可选复核另外计数。即便只运行免费观察期，只要启用了 Manager，仍需可用的 Manager 模型服务。

## 9. 主要输出与审计

实验目录根部保存 MATSim 输出和 `effective-config.xml`；平台记录位于 `morning/`。多数逐行记录为 UTF-8 `jsonl.gz`。文件按实际启用功能及事件生成，缺失文件不能直接等同于数值为零。

| 文件 | 内容 |
| --- | --- |
| `manifest.json`、`effective-config.xml` | 生效设置、版本、种子、输入及相关哈希、MATSim 配置。 |
| `status.json`、`progress.json`、`api-usage.json` | 完成情况、当前阶段、模型请求与可用的用量统计。 |
| `cohort`、`profiles`、`information-groups`、`candidates`、`candidate-quality` | 目标行程、人群分组、画像、路线候选及质量信息。 |
| `decisions`、`executed-route-checks`、`experiences`、`trips` | 决策、实际执行检查、每日个人经历和行程记录。`trips` 可按 `--trip-output-interval` 抽稀，`experiences` 逐日保留。 |
| `baseline-contexts`、`baseline-choices` | MNL 输入、动作效用、概率、随机数和选择。 |
| `decision-contexts`、`attempts`、`llm-results`、`memory-*` | LLM 旅客输入、调用、输出及记忆更新。 |
| `policies`、`policy-applications`、`toll-observations`、`toll-payments`、`payment-memory-final` | 政策、生效情况、实际观察、付款及最终个人收费认知。 |
| `manager-contexts`、`manager-attempts`、`manager-decisions`、`manager-memory-*` | Manager 输入、政策尝试、决策和每日反思；可选保护机制另有 `manager-safety-*`。 |
| `metrics`、`link-hours` | 每日及路段/时间箱交通指标；`metrics` 同时包含目标人群分组和全天汽车交通汇总。 |

每日目标行程指标包括出发、完成和受困数量，平均及 P95 汽车耗时、门到门耗时、超额延误、最慢 5% 平均耗时、路线距离与自由流时间、入网前等待、迟到与准时情况，以及路线和出发时间变化。另按受控/原生与知情/不知情组提供部分指标；路段和全天汇总覆盖范围与目标行程不同。

分析时使用 `day + tripId` 关联多日决策与经历；使用 `policyId`、`policyVersion`、`policyFingerprint` 区分执行政策。目标人群指标、已出发者完成率、全部计划行程完成率以及全网汽车人时具有不同分母，不能直接混用。

正常结束时先关闭 JSONL 文件并检查 gzip、换行、写入数和关键记录数，生成 `integrity.json`，再写出 `status.json` 中的 `complete=true`、`integrityVerified=true`。大规模事件账本会增加存储以及结束时的检查耗时。复制后可复核：

```powershell
python scripts/verify_run_integrity.py "实际实验目录/morning"
```

该检查覆盖 OutputWriter 产生的 JSONL 文件及清单记录，不证明数据语义正确、身份唯一，也不覆盖所有 MATSim 原始 events。原始 events 默认按 MATSim 配置间隔输出，不能假定每天都有。当前输出也不是可恢复全部仿真状态的自动断点续跑检查点。

## 10. 常用运行示例

以下命令从项目根目录执行；先用 `.\mvnw.cmd -DskipTests package` 打包。`--validate-only` 只准备并检查输入，不运行 QSim 或调用模型，输出为 `validated=true`，不能视作完整仿真结果。

```powershell
$Jar = 'matsim-example-project-0.0.1-SNAPSHOT.jar'
$App = 'org.matsim.agentic.MorningExperiment'
$Common = @('--config','scenarios/SiouxFalls-public/config.xml',
  '--mode','hybrid','--demand','100','--sample-rate','0.2',
  '--days','100','--population-seed','6021','--seed','268')

# 原生旅客，无 Manager
java -Xmx8g -cp $Jar $App @Common --policy mnl --llm-agents 0 --output 'output/native-seed-268'

# MNL 旅客，无 Manager；不调用模型 API
java -Xmx8g -cp $Jar $App @Common --policy mnl --llm-agents all --mnl-choice-seed 268 --output 'output/mnl-seed-268'

# 原生旅客 + LLM Manager；需要配置 Manager 模型服务
java -Xmx8g -cp $Jar $App @Common --policy mnl --llm-agents 0 --manager --manager-profile basic --max-requests 500 --output 'output/native-manager-seed-268'

# LLM 旅客 + LLM Manager：示例控制 3 人；需要配置模型服务
java -Xmx8g -cp $Jar $App @Common --policy llm --llm-agents 3 --manager --manager-profile basic --max-requests 10000 --output 'output/llm-manager-seed-268'
```

正式批量运行前可附加 `--validate-only` 检查输入，并查看控制台的实际目标行程数和 `minimumLlmCalls`，再设置足够的请求预算并预计费用；将 `--llm-agents` 改为 `all` 会显著增加模型调用。项目还提供 [三种 MNL/Manager 多种子脚本](../scripts/run_mnl_three_seeds.ps1) 和 [通用 PowerShell 脚本](../scripts/run_public_experiment.ps1)。三种子脚本不指定候选文件时逐次生成；为确保配对实验的路线一致，可用 `-CandidateFile` 显式复用经过验证且覆盖目标 OD 的缓存。

自动目录或显式输出路径重名时，程序可能保留新编号目录；应以控制台打印的实际输出路径为准。多种子配对至少固定人口输入与抽样、容量、目标人群、画像、信息分组、候选路线、时间网格、天数及可比较的政策条件；固定种子不保证不同旅客模型第一天选择相同，也不保证远程 LLM 输出完全确定。固定政策比较更适合隔离旅客效应；各组各自运行 Manager 时，结果反映旅客与政策共同变化的闭环系统。
